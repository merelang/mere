Game Boy — written in Mere

A Sharp LR35902 (Game Boy) emulator compiled from Mere to WebAssembly. The same machine that passes Blargg's cpu_instrs suite (11/11, interrupts included) on all four Mere backends — CPU, timer, interrupt controller, PPU, and MBC1 cartridge banking — here renders to a <canvas>, driven per frame by dom_on_frame.

Running dmg-acid2, the reference PPU test: the head is the background, the header text is the window, and the eyes / nose / mouth are sprites. The cartridge is served to the Wasm module a byte at a time via a small dom_rom_byte host import, and the 160×144 framebuffer is blitted with the classic DMG green palette.

What's happening

  1. mere -w -I . gameboy.mere lowers the whole machine — the LR35902 core, the timer/interrupt spine, the scanline PPU, and MBC1 banking — to WebAssembly.
  2. The page fetches dmg-acid2.gb and hands it to the glue (setRom); the module pulls it in through dom_rom_size / dom_rom_byte.
  3. Each requestAnimationFrame runs a slice of the CPU (advancing the timer, PPU, and interrupts) and repaints the framebuffer via dom_canvas_fill_rect.
