# scripts/wasm_size_budget.txt -- bands for the .wasm the docs site ships.
#
# One line per file: <name> <floor> <ceiling>, in bytes.
# scripts/wasm_size_check.sh builds the site and fails outside the band.
#
# THESE ARE POST-wasm-opt. build_full.sh runs `wasm-opt -Oz` on every module,
# which is about a third of the playground's bytes, so a build without it
# measures a different artifact -- the check skips rather than compare across
# that line.
#
# Each band is the size measured on 2026-09-12, -10% / +10%. Not targets: the
# ceiling is tight enough that the 2026-07 -> 2026-09 tripling of hello.wasm
# would have failed here long before anyone saw it by eye. The floor exists
# because a demo that collapses to a stub is a failure a ceiling-only check
# calls a pass forever -- the reasoning is scripts/budget_check.sh's.
#
# The floor these bands sit on is not free space. After -Oz, hello.wasm is 101
# functions, 65 of them rooted by the elem segment because every Mere closure
# call goes through the function table. Remove the table (a broken module,
# measured only as a bound) and the same program is 7 functions and 2,299 B.
# Shrinking that is compiler work, not band work: do not lower these by hand
# hoping to force it.
#
# The optimizer is part of the measurement. Recorded with:
# wasm-opt: 132
# ci.yml and pages.yml pin the same version; ubuntu's apt binaryen (108) cannot
# read these modules at all.
#
# Moving a band is a decision, not maintenance: say why in the commit.
