# scripts/wasm_size_budget.txt -- bands for the .wasm the docs site ships.
#
# One line per file: <name> <floor> <ceiling>, in bytes.
# scripts/wasm_size_check.sh builds the site and fails outside the band.
#
# THESE ARE POST-wasm-opt. build_full.sh runs `wasm-opt -Oz` on every module,
# which is about a third of the playground's bytes, so a build without it
# measures a different artifact -- the check skips rather than compare across
# that line.
#
# Each band is the size measured on 2026-09-21 with Q-139 complete (raytrace
# re-measured with Q-141), -10% / +10%. Not targets: the
# ceiling is tight enough that the 2026-07 -> 2026-09 tripling of hello.wasm
# would have failed here long before anyone saw it by eye. The floor exists
# because a demo that collapses to a stub is a failure a ceiling-only check
# calls a pass forever -- the reasoning is scripts/budget_check.sh's.
#
# The floor these bands sit on is not free space. After -Oz, hello.wasm is 101
# functions, 65 of them rooted by the elem segment because every Mere closure
# call goes through the function table. Remove the table (a broken module,
# measured only as a bound) and the same program is 7 functions and 2,299 B.
# Shrinking that is compiler work, not band work: do not lower these by hand
# hoping to force it.
#
# The optimizer is part of the measurement. Recorded with:
# wasm-opt: 132
# ci.yml and pages.yml pin the same version; ubuntu's apt binaryen (108) cannot
# read these modules at all.
#
# Moving a band is a decision, not maintenance: say why in the commit.
#
# 2026-09-21, Q-139: every band moved DOWN, by 4% to 29%, and the total went
# 616,469 -> 522,611 B. Not a shrunk feature -- a `_closure` adapter used to be
# emitted for EVERY top-level fn, and the elem table it sits in is a root the
# pruner cannot see past, so every curried body shipped whether or not anything
# could reach it. Emitting the adapter only for fns actually used as values,
# and the curried body only when something can still enter it, let the pruner
# do the work it was already capable of. gameboy -29%, raytrace -26%, chip8
# -22%, selfhost-tyck -19%. The second half of Q-139 (the uncurried entry on
# closure VALUES: two-argument adapters, and the branch in each of the three
# higher-order helpers) put 7% back, so the settled total is 558,305 B against
# 616,469 before the arc -- these bands are that settled state, measured once
# rather than chased slice by slice.
#
# Checked before the bands moved, because a floor exists to catch exactly the
# mistake this would look like: suite 2773, parity 196/0, the bootstrap tests
# that RUN the self-hosted compiler under node, and this file's own behaviour
# check (3 of 3 optimized modules answer what the interpreter does).
# v0.1.708: range-versioning now proves bound and index arithmetic before
# selecting unchecked accesses. With wasm-opt 132, chip8 grows 6344 -> 6820 B
# and gameboy 15326 -> 16728 B. This is the cost of the added safety guards,
# not a removed demo: three frames of each optimized module produce identical
# drawing operations before and after the change. Recenter only these two
# bands at the measured size, retaining the -10% / +10% policy.
